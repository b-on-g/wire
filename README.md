# $bog_wire

Язык wire: реактивные методы как в `$mol_wire`, соглашения MAM, без GC. Компилятор на TS, генерирует C, который собирает `zig cc`.

```sh
node bog/build2/start/-/node.js bog/wire/shop
```

```sh
bog/wire/shop/-/native
```

Сборка пака с `.wire` разбирает и проверяет все его исходники, генерирует C в `-/wire/test/main.c`, собирает его `zig cc` вместе с рантаймом и запускает тесты. Красный тест, ошибка проверки или утечка роняют сборку. Если в `.native.wire` есть `action main()`, рядом собирается бинарь `-/native`. Плагин подключает `wire.build.ts`, паки внутри `bog/wire` получают его сами.

## Без сборщика MAM

Компилятор есть и отдельной командой. Её один раз собирают в бандл, дальше она работает сама: находит модули по `$имя` от текущей папки, проверяет, генерирует C и зовёт `zig cc`.

```sh
node bog/build2/start/-/node.js bog/wire/cli
node bog/wire/cli/-/node.js build bog/wire/demonative/hello
bog/wire/demonative/hello/-/native
node bog/wire/cli/-/node.js test bog/wire/demonative
node bog/wire/cli/-/node.js c bog/wire/demonative/hello > main.c
zig cc -std=c11 -O2 -Ibog/wire/rt -o hello main.c bog/wire/rt/rt.c
```

`build` собирает `-/native` из `action main()` в `.native.wire` самого модуля, `test` собирает и запускает тесты, `c` печатает C.

## Язык

```wire
object $bog_wire_shop_line {

	sku: text
	cart: $bog_wire_shop_cart
	catalog: $bog_wire_shop_catalog

	qty = cart.qty( sku )

	sum = catalog.price( sku ) * qty

	label = "{sku} x{qty} = {sum}"

}
```

- Только методы, переменных нет. `имя = выражение` — мемо, с параметрами — мемо по ключу. `next?` последним параметром — состояние: без аргумента читает, с аргументом пишет.
- `solid` как `$mol_wire_solid()`: состояние не убирается после ухода подписчиков.
- `action имя( … ) { … }` — действие, единственное место, где можно писать в состояние и звать другие действия. Тела мемо чистые.
- Свойство без тела (`sku: text`) задаёт владелец: `$bog_wire_shop_line { sku <= sku }`. `<=` как в `view.tree`. `$x()` — объект без привязок.
- `type $x { поле: тип }` — неизменяемая запись, `$x{ поле, другое: выражение }`.
- Лямбд нет: в `map`, `find`, `upsert`, `drop` передаются методы.
- Типы: `int`, `float`, `bool`, `text`, `list T`, `T?`, `$fqn`. Тексты с подстановкой `"{x}"`, экранирование `\{ \} \" \\ \n \t`.
- Глобальные имена с `$`, по ним MAM находит модуль, импортов нет. Теги файлов `.test.wire`, `.native.wire`, `.web.wire`.
- Тест — действие объекта в `.test.wire`.
- `action main()` в `.native.wire` — точка входа. Каждое действие — задача, после задачи тик убирает атомы без подписчиков. `after( действие )` ставит действие без параметров следующей задачей, `print( text )` печатает строку, `list.join( sep )` склеивает тексты.
- Что должно пережить тик без подписчиков, помечается `solid`, как в моле: `solid shop = $bog_wire_shop()`.
- `stdin( n ): text?` — строка ввода номер n, `none` после конца ввода. Чтение чистое, доступно и в мемо. Пока строки нет, вычисление ждёт, как в моле: мемо прерывается и пересчитывается, когда строка придёт, а действие перезапускается с начала, и уже выполненные эффекты (запись, `print`, `after`, `assert`) пропускаются по порядку. Асинхронность псевдосинхронная: ни `async`, ни колбеков. В тестах ввод пуст.
- В действии инструкцией может быть `условие ? эффект : эффект`, ветка может быть `none`.
- `&&` и `||` вычисляются коротко, на этом держится рекурсия вида `n > 0 && down( n - 1 )`.
- `self` — текущий объект, нужен, чтобы отдать себя создаваемому: `sheet <= self`.
- Текст: `size`, `trim`, `chars`, `int`, `float` (два последних дают `none`, если не число), `slice( from, to )`, `find( part ): int?`, `split( sep )`. Позиции считаются в символах, не в байтах. Внутри `{…}` можно писать текстовые литералы.

## Модули

- `lex` — текст в токены с позициями `$mol_span`.
- `parse` — токены в дерево программы, ошибки `$mol_error_syntax` с местом.
- `check` — проверка программы целиком: имена, типы, чистота мемо (без записи, действий и `assert`), инструкции действий только с эффектом, все свойства без тела привязаны через `<=`, операции над списками принимают метод с подходящим ключом. Ошибки копятся списком `$mol_error_syntax`, тип мемо выводится из тела, цикл вывода требует объявить тип.
- `emit` — дерево программы в C. Каждый метод объекта становится функцией пересчёта атома, действие — функцией, привязка `<=` — функцией в контексте владельца, которая видит параметры места создания.
- `rt` — рантайм на C. Граф как в `$mol_wire`: атомы, подписки, «сомнение» и пересчёт по запросу, уборка атомов без подписчиков, `solid`. Объект принадлежит первому поймавшему его атому и умирает вместе с ним. Значения неизменяемы и живут по счётчику ссылок, циклов из них не собрать. Промежуточные значения тела держит область вычисления и освобождает разом, в том числе при прерывании ожиданием. Цикл событий выполняет задачи, а когда задач нет и кто-то ждёт ввода, читает следующую строку. После каждого теста корень уничтожается и проверяется, что не осталось ни узлов, ни значений.
- `source`, `bundle` — плагин к `$bog_build2`: зависимости `.wire` по `$имя`, сборка и прогон тестов.
- `ast` — типы дерева, `ast/dump` — печать дерева S-выражениями для тестов.
- `shop` — пример на wire: каталог, корзина, строки, магазин и его тесты.
- `demonative` — реактивная таблица в терминале на wire.
